ES Module (ESM) adalah cara bawaan JavaScript untuk memecah kode ke banyak file dan menyambungkannya kembali. Ia hadir bersama ECMAScript 2015 (ES6) dan menjadi standar yang mendasari seluruh ekosistem modern.

Sebelum ESM, tidak ada jawaban resmi, jadi komunitas membuat caranya sendiri: IIFE, CommonJS (Node.js), AMD (RequireJS), UMD. ESM menggantikan tambal sulam itu dengan satu sintaks yang berjalan native di browser dan Node.

## Export dan import

Kita tandai apa yang dibagikan sebuah file dengan `export`, lalu menariknya ke file lain dengan `import`.

```javascript
// utils.js
export function sum(a, b) {
  return a + b
}

export const PI = 3.14159

export default function greet(name) {
  return `Hello, ${name}!`
}
```

Ada dua jenis: **named export** (boleh banyak dalam satu file) dan satu **default export** per file.

Sisi import-nya mengikuti bentuk yang sama:

```javascript
// app.js
import greet from './utils.js' // default
import { sum, PI } from './utils.js' // named
import { sum as addNumbers } from './utils.js' // dengan alias
import * as Utils from './utils.js' // semuanya, sebagai namespace

console.log(greet('World')) // "Hello, World!"
console.log(sum(2, 3)) // 5
console.log(Utils.PI) // 3.14159
```

## Bedanya dengan CommonJS

Kalau kamu pernah pakai CommonJS di Node, sintaksnya mirip tapi modelnya berbeda:

```javascript
// CommonJS
const { sum } = require('./utils.js')
module.exports = { myFunction }

// ES Module
import { sum } from './utils.js'
export const myFunction = () => {}
```

Perbedaan utamanya, `import`/`export` di ESM bersifat **statis**: tetap di bagian atas file dan dianalisis sebelum kode dijalankan. `require()` di CommonJS bersifat dinamis dan diselesaikan saat runtime. Struktur statis inilah yang memungkinkan bundler melakukan *tree shaking*: karena mereka tahu persis apa yang di-import, export yang tidak dipakai bisa dibuang.

## Di browser

Tambahkan `type="module"` pada `<script>` dan browser memperlakukannya sebagai ESM:

```html
<script type="module">
  import { sum } from './utils.js'
  console.log(sum(1, 2))
</script>

<script type="module" src="app.js"></script>
```

Ada beberapa konsekuensinya: script module berjalan dalam mode strict, dieksekusi secara asinkron, di-fetch dengan CORS, dan butuh server sungguhan — `file://` tidak akan jalan.

## Import dinamis

`import` juga bisa dipakai sebagai fungsi yang mengembalikan promise, jadi sebuah module bisa dimuat hanya ketika benar-benar dibutuhkan:

```javascript
button.addEventListener('click', async () => {
  const { renderChart } = await import('./chart.js')
  renderChart(data)
})
```

Di sini `chart.js` tidak diunduh sampai tombolnya diklik — dasar dari code splitting dan lazy loading, yang menjaga muatan awal halaman tetap ringan.

Segitu intinya. Setiap framework dan build tool modern (React, Vue, [Vite](https://vite.dev/), [Rollup](https://rollupjs.org/)) dibangun di atas fondasi `import`/`export` yang sama, jadi memahaminya sangat berguna.
