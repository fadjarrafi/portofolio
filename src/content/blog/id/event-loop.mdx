## Apa itu event loop di javascript?

JavaScript bersifat single thread. Kode dijalankan satu instruksi demi satu instruksi secara berurutan, dan hanya satu hal yang bisa terjadi dalam satu waktu.

Kedengarannya membatasi, tapi justru event loop-lah yang membuat JavaScript bisa menangani operasi lambat tanpa membekukan yang lain. Operasi itu dijalankan di samping, jadi instruksi lain yang masih antre tidak perlu ikut berhenti.

## Operasi Web API yang Memakan Waktu

Beberapa operasi browser cukup lambat sampai kita tidak mau menunggunya begitu saja:

1. **Fetch / XMLHttpRequest** — permintaan jaringan bisa berlangsung dari ratusan milidetik hingga beberapa detik, bergantung pada koneksi dan besarnya data yang kembali. Misalnya `fetch('https://api.example.com/data')` yang menarik dataset besar.
2. **FileReader** — membaca berkas besar yang diunggah pengguna, seperti `fileReader.readAsDataURL(largeImageFile)`.
3. **IndexedDB** — membaca atau menulis data dalam jumlah banyak, seperti `indexedDB.getAll()` pada store dengan ribuan entri.
4. **Media processing** — mendekode dan memutar audio atau video besar, seperti `video.play()` pada klip 4K.
5. **Geolocation** — `navigator.geolocation.getCurrentPosition()` bisa lambat, terutama pada perangkat dengan sinyal GPS lemah.

Kalau JavaScript menjalankan semua ini di thread utama, seluruh aplikasi akan berhenti menunggu satu per satu selesai. Maka JavaScript tidak melakukannya. Operasi berat diserahkan ke Web APIs, yang hidup di luar thread utama.

Bayangkan sebuah `fetch` yang mengunduh dataset 10MB. Tangani langsung di thread utama, dan UI membeku selama seluruh proses unduhan — tidak bisa menggulir, mengeklik, atau apa pun sampai datanya tiba. Dengan event loop, JavaScript menjalankan `fetch`, lanjut ke baris berikutnya, dan pengguna tetap bisa berinteraksi. Begitu unduhan selesai, callback-nya menunggu di queue sampai Call Stack kosong, lalu dijalankan.

Itulah arti "non-blocking": operasi lambat tidak pernah mengunci thread utama. Tugas berat berjalan di latar belakang sementara aplikasi tetap responsif.

Event loop bertanggung jawab untuk:

- mengatur apa yang jalan dan kapan
- mengumpulkan dan memproses event
- menjalankan tugas yang sedang antre di queue

Ia menangani tiga jenis pekerjaan:

1. **Synchronous task** dijalankan langsung di Call Stack.
2. **Microtask** adalah tugas asinkron berprioritas tinggi, seperti callback Promise.
3. **Macrotask** adalah tugas asinkron berprioritas lebih rendah, seperti `setTimeout`.

Dan komponen tempat pekerjaan itu berpindah:

- Call Stack
- Web APIs
- Callback Queue (macrotask)
- Microtask Queue
- Event Loop itu sendiri

## Cara Kerja Event Loop, Langkah demi Langkah

Intinya siklus ini:

1. Jalankan semua kode sinkron di Call Stack.
2. Kuras seluruh Microtask Queue.
3. Ambil satu tugas dari Callback Queue.
4. Ulangi.

Prioritas di langkah 2 dan 3 inilah yang sering terlewat: semua microtask harus habis dulu sebelum satu macrotask dijalankan. Jadi sebuah `Promise.then` yang dijadwalkan setelah `setTimeout(…, 0)` tetap jalan lebih dulu.

Lebih rincinya:

1. **Kode sinkron jalan lebih dulu.** Fungsi masuk ke Call Stack, dieksekusi, lalu keluar, satu per satu.
2. **Operasi asinkron didelegasikan.** Saat JavaScript menemui sesuatu seperti `setTimeout`, `fetch`, atau event listener, operasinya diserahkan ke Web APIs supaya berjalan di luar stack.
3. **Callback masuk antrean.** Setelah operasi asinkron selesai, callback-nya masuk ke queue — callback Promise ke Microtask Queue, sisanya ke Callback Queue.
4. **Loop menguras queue.** Setiap kali Call Stack kosong, event loop membersihkan semua microtask lebih dulu, lalu mengambil satu macrotask, dan memindahkannya ke stack untuk dijalankan.
5. **Ulangi.** Siklus terus berputar selama masih ada pekerjaan, dan begitulah JavaScript tetap asinkron tanpa pernah memblokir thread utama.
